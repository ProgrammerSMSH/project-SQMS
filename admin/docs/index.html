Token Mechanism

How tokens are generated with strict data integrity to avoid double-numbering.

Atomic Incrementation

Using MongoDB's $inc operator, the system ensures that token numbers are unique even if multiple patients register at the exact same microsecond.

Backend Logic
const updatedQueue = await Queue.findByIdAndUpdate( queueId, { $inc: { lastTokenNumber: 1 } }, { new: true } ); const tokenNumber = `${queue.code}-${updatedQueue.lastTokenNumber}`;

The "Call Next" Pipeline

When a clinician clicks "Call Next", the system executes a complex multi-step validation and notification pipeline.

1. Auth & Validation

Verify clinician's JWT session, counter status (must be ACTIVE), and authorization to serve the requested Medical Department.

2. Token Selection

Execute the Priority-First Search to find the most suitable patient token in the database.

3. State Mutation

Atomically update Token status to SERVING and assign the target counterId.

4. Notification Blast

Trigger Firebase FCM to the called patient's mobile device and broadcast Socket.io event to all TVs.

Priority Search Algorithm

To ensure patients with urgent needs are seen first, the engine uses a Tiered Search Loop.

Algorithm View
const priorities = ['EMERGENCY', 'SENIOR', 'GENERAL', 'NORMAL']; let nextToken = null; for (let p of priorities) { let query = { status: 'WAITING', priority: p }; if (queueId) query.queueId = queueId; nextToken = await Token.findOne(query) .sort({ joinedAt: 1 }) // First-come, first-served within tier .populate('userId'); if (nextToken) break; // First matching priority wins }
Why this works:

It guarantees that an "Emergency" patient will ALWAYS be called before any "General" patient, regardless of when they arrived. Within the same priority tier, the system respects the joinedAt timestamp for fairness.
