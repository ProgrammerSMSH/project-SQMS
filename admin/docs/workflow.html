Simulation Events IDLE

Patient Initiates Join

System is on standby. The patient app is ready to request a token from the central hospital server.

Event: Dispatch Token Request

Patient clicks 'Join'. A POST request is fired to /api/v1/tokens/generate containing the department ID and JWT session.

Server: Logic Extraction

Node.js validates the JWT. It scans the Department model to find the lastTokenNumber and prepares a new sequence.

Cloud: Atomic Write

The server performs a $inc operation on MongoDB. This ensures the token number is unique even if 100 people join at once.

App: Reactive UI Update

Server returns JSON response. Patient app catches the data and immediately displays the token (e.g., T-105) with estimated wait time.

Clinician: Command Sent

Doctor clicks 'Call Next'. A trigger is sent to the counterController.callNext endpoint.

Server: Priority Rank Search

Engine initiates a rank-based search: EMERGENCY > SENIOR > GENERAL. It finds the next patient based on waiting time.

DB: State Mutation

The Token record is updated from WAITING to SERVING. The clinic room ID is attached to the token record.

Live: Socket.io Broadcast

Server emits update_display event. All Public TVs receive the new token number and play a chime sound instantly.

Alert: Patient Notification

Firebase Cloud Messaging (FCM) fires a push alert to the patient's phone. The app vibrates to tell them to enter Room 5.
